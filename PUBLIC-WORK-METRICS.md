# Public work metrics methodology

Updated: August 15, 2026

This methodology defines the dated public-work metrics used alongside the evidence index. Each metric measures public engineering or field-research activity, while the evidence ledger identifies acknowledgement and implementation influence separately.

## Metric definitions

| Public metric | Definition | Source packet |
| --- | --- | --- |
| Public GitHub contributions in the past 12 months | The public contribution total shown on Roman's GitHub profile for the stated snapshot date | Profile URL, snapshot date, 12-month window, captured total |
| Public AI-agent discussions reviewed | Distinct public GitHub records that meet the documented agent and consequential-action relevance criteria | Inclusion criteria, unique record key, de-duplication rule, snapshot date, total |
| Public agent projects mapped | Distinct public projects or repositories in the dated Neura field map | Inclusion criteria, project key, de-duplication rule, snapshot date, total |

## Inclusion rules

The discussion metric includes a public GitHub record once when it concerns an AI-agent, agent-runtime, MCP, authorization, approval, action-governance, or outcome-evidence surface and has a stable repository-plus-issue-or-pull-request identity. The project metric counts each distinct public project once, regardless of its number of relevant discussions.

## Current publication gate

Each public figure will be published with its dated source snapshot and reproducible calculation. The source-linked evidence index will keep activity volume, direct acknowledgement, implementation influence, and field insight visibly distinct.
